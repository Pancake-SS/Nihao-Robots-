## Use the portable SDK

`scripts/flutter.ps1` uses `NIHAO_FLUTTER_ROOT` when supplied, an SDK on PATH, then the persistent LocalAppData installation, then the legacy Temp installation. It never edits global/user PATH. Temp directories can be cleaned by Windows; for a permanent install follow the official [Flutter installation instructions](https://docs.flutter.dev/install/with-vs-code), then point `NIHAO_FLUTTER_ROOT` to that SDK or put it on PATH.

From the project root in PowerShell:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\flutter.ps1 --version
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\flutter.ps1 doctor -v
$dartTool = Join-Path $env:LOCALAPPDATA 'NihaoRobotTools\flutter\bin\dart.bat'
& $dartTool format --output=none --set-exit-if-changed .
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\flutter.ps1 analyze --no-pub
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\flutter.ps1 test --no-pub
```

`--no-pub` uses the already-resolved dependencies and avoids repeating native plugin symlink setup. On a fresh machine run `flutter pub get` after enabling Windows Developer Mode. For a different SDK, adjust the Dart executable path. Do not rerun `bootstrap_windows.ps1` on the current project: its runner and metadata already exist, and the script correctly refuses to overwrite them.

## Native Windows launch

### Recover a missing temporary Dart runtime

If the wrapper reports a missing cached Dart runtime (or Flutter exits with only `The system cannot find the path specified`), check the SDK itself. On 2026-11-04 the portable SDK's `bin/cache/dart-sdk` directory was missing while `engine-dart-sdk.stamp` remained. The cause of removal was not established. The wrapper now detects this mismatch explicitly.

For the current persistent installation, close other Flutter commands, preserve a stale marker if present, then allow Flutter to download its matching runtime again:

```powershell
$sdkCache = Join-Path $env:LOCALAPPDATA 'NihaoRobotTools\flutter\bin\cache'
$stampPath = Join-Path $sdkCache 'engine-dart-sdk.stamp'
if ((Test-Path -LiteralPath $stampPath) -and -not (Test-Path -LiteralPath (Join-Path $sdkCache 'dart-sdk\bin\dart.exe'))) {
    Rename-Item -LiteralPath $stampPath -NewName ('engine-dart-sdk.stamp.missing-runtime-' + [guid]::NewGuid().ToString('N'))
}
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\flutter.ps1 --version
```

This repairs only SDK cache state, not learner data. For a custom SDK, use its actual cache path. A permanent SDK location outside Temp is preferable for regular development; configure `NIHAO_FLUTTER_ROOT` as described above.

A direct CMake configure of `windows/` can fail with missing `flutter/ephemeral/generated_config.cmake`. This file is generated by Flutter, not a file to invent or commit. The reported VS Code command configured CMake before Flutter prepared it and used the unsupported workspace path containing `!`.

Workspace settings now disable automatic CMake configuration on open/edit. See [Microsoft's CMake Tools settings](https://github.com/microsoft/vscode-cmake-tools/blob/main/docs/cmake-settings.md). Use **Ctrl+Shift+B → Ni Hao Robot: build Windows**, or the PowerShell command below; it stages sources in a supported path and lets Flutter generate the configuration. Visual Studio still supplies the compiler. A manual CMake Configure now gives an actionable Flutter build instruction when generation is missing. The original CMake cache and learner data are preserved.

### Build and open the app

On a new machine, follow the official [Windows desktop setup](https://docs.flutter.dev/platform-integration/windows/setup): install Visual Studio with **Desktop development with C++** and its default components. VS Code alone does not include this compiler. Enable **Developer Mode** in Windows Settings so Flutter can create native-plugin symlinks. Both prerequisites now pass on this machine following the user's setup; these machine settings were not changed by the build helper. The Android SDK is unnecessary for the Windows build, and the wrapper handles Flutter being absent from PATH.

Flutter's native builder also rejects the `!` in this workspace's name. Keep the workspace in place and use the safe-path staging helper:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\build_windows.ps1
```

The helper copies only `lib`, `assets`, `windows`, `pubspec.yaml`, `pubspec.lock` and `.metadata` to a new `%TEMP%\nihao-windows-...` directory, resolves packages there and builds a debug executable. It prints the executable path on success. It does not copy learner data, the reference deck, source robot inventory, `.git`, `.venv` or editor settings. The source snapshot is retained for inspection; subsequent edits require a new build. Use `-Configuration release` for a release build only after native smoke tests pass.

The implemented flow is Create Local Profile > Choose > Continue > Home. Vocabulary > Browse words opens a priority queue of all 11,147 words in pages of 20. In the quiz, select or type an answer and press Check answer. Wrong questions return at the end until corrected; every correct first response adds one cumulative correctness point. Open Practice from the sidebar or Vocabulary to replay a selected word's full test, choose a number of random questions from distinct learned words, or continue through fresh random questions. One-word tests and relearning open with browsable 20-word pages; select a word or use its row action immediately, and search by Hanzi or English meaning when useful. Master practice uses the same picker, while Instant master browses the whole unmastered library in 20-word pages. Practice is available immediately with no due timer. All words have seven or eight questions; available source examples and audio vary by word. The first queue visit installs the bundled curriculum once, so allow it to finish. No web server or runtime download is needed.

Practice opens a menu of four separate pages: one-word test, counted random questions, endless questions, and relearning. Vocabulary > Master offers a full test for words with 25 correct points. Instant master moves a word you already know directly into Master after confirmation, without a quiz or points requirement. The Mastered words list lets you practice a specific word again; a word returns to Learn after three missed answers in a session. Its correctness points remain saved. Historical Master writing from older app versions remains in account saves but is no longer requested or shown.

Instant master is also available for the selected word on Vocabulary > Learn and at the end of its lesson. A confirmation explains that it skips both the point threshold and quiz. Choosing **Not now** returns to learning without changing the word.
